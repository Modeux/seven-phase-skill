# seven-phase

一個給 Claude Code 用的 skill：把「做一個功能／修一個 bug」拆成七個階段，每個階段結束都停下來跟你報告、等你說「繼續」才往下走。

## 這是在解決什麼問題

讓 AI 一口氣從頭做到尾，常見的結果是：做了半天才發現方向從一開始就錯了，或是程式碼進了版本歷史你才第一次看到。這個 skill 把控制權留在你手上：

- **每個階段都停**：AI 先報告做了什麼、為什麼這樣決定、接下來要幹嘛，你說「繼續」它才動。
- **先想清楚再寫程式**：研究、討論、訪談、計畫這四步都做完，你核准了，才開始寫程式碼。
- **程式碼先測後寫**：先寫一個會紅的測試，再寫讓它變綠的程式碼。
- **多方審查**：寫完後派多個獨立的審查員從不同角度看（語言慣例、安全、測試品質、註解是否誤導……），再把所有發現去重、逐條裁決。
- **你沒說，它不 commit、不 push。**

## 七個階段

| 階段 | 做什麼 | 產出 |
|---|---|---|
| 1 Research | 看現況、找出相關程式碼、挑戰需求本身合不合理 | `RESEARCH.md` |
| 2 討論 | 跟你確認方向，把「方向錯誤」提前到碰細節之前發現 | `SPEC.md` 的方向決議 |
| 3 Interview | 一題一題問清楚細節與取捨 | `SPEC.md` 完整規格 |
| 4 Plan | 寫實作計畫；大包先給內部一顆＋三方外審看過 PLAN，你核准前不寫一行正式程式碼 | `PLAN.md` |
| 5 TDD 實作 | 紅測試 → 綠程式碼 → 重構，一片一片做 | 程式碼 |
| 6 多方審查 | 派多個審查員各看一個面向，整理成去重後的發現地圖 | `REVIEW.md` |
| 7 收斂 | 逐條裁決審查發現、修、跑全部測試與檢查、總結 | 裁決表、總結 |

小而明確的任務（修法已定、不碰錢／權限／敏感面、約 300 行以內）可以走**精簡路**：省掉討論、訪談與中間的停點，但審查一樣不省。

所有過程記錄都放在專案裡的 `.claude/PRPs/plans/<任務名>/`，換一個 session 或 context 被壓縮後，AI 讀那裡的 `PROGRESS.md` 就能接著做。

## 怎麼用

把這個 repo 放到 `~/.claude/skills/seven-phase/`（或專案的 `.claude/skills/` 底下），之後在 Claude Code 裡說：

- 「這個功能走七階段」—— 開始一個新任務
- 「繼續」／「下一階段」—— 在停點放行
- 「繼續 <任務名>」—— 接續之前做到一半的任務
- 「進度」—— 看所有任務的看板

## 目錄

```
SKILL.md       入口：開工步驟、分流判準、停點協定、全程規則、模型與 agent 分工
phases/        每個階段各一份做法（1-research.md … 7-converge.md），精簡路在 lean.md
references/    用到才讀：審查路數怎麼配、外部審查、規則的由來、專案特定設定
assets/        範本：審查任務書、PLAN 審查任務書、收斂驗證任務書、修復任務包、停點回報、走一趟套件
scripts/       可重用腳本：進度看板、凍結快照與 worktree、審查覆蓋率、花費統計、摘錄任務書
evals/         skill 的評測案例
```

常用腳本（都只用 Python 標準函式庫）：

| 腳本 | 做什麼 |
|---|---|
| `board.py` | 掃所有任務的 `PROGRESS.md`，印出跨任務進度看板 |
| `mkpatch.py` / `mkworktree.py` / `checktree.py` | 把未 commit 的改動凍成快照，開隔離的 worktree 給審查員與修復者用，並驗證沒被動過 |
| `merge_back.py` | 把修復 worktree 裡的改動搬回主工作樹 |
| `numstat.py` | 算這次改動的正式碼／測試／文件行數，決定審查規模 |
| `extract.py` | 從文件逐字摘錄段落進派工任務書（不改寫，附出處） |
| `reviewcov.py` | 檢查每個審查員都交件了、發現地圖沒漏條目 |
| `run_external.py` | 跑外部審查（codex / grok / agy） |
| `dockerslot.py` | 吃 Docker 的指令排隊（同時最多 N 條），讓 agent 一波派完不必分波 |
| `agentcost.py` / `taskcost.py` / `laneyield.py` / `claudemdcost.py` | 從對話紀錄算花費：每顆 agent、每個任務、每條審查路買到了什麼、指令檔載入成本 |

## 改規則之前

每條規則都是一次踩坑換來的。覺得某條多餘，先讀 `references/history.md` 看它在防什麼；改完在那張表加一行，並在這個目錄 commit。

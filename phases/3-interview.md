# 第 3 階段：Interview

目標：以 SPEC 的方向決議為前提，問到決策樹每個分支都有結論。**不重問討論已定案的事項。**

套 `mattpocock-skills:grilling`，提問一律 AskUserQuestion。白話協議（判準：不熟本專案的工程師讀完要能直接作答，讀不懂就重寫）：
- 先兩三句日常語言交代脈絡（現在情況、為什麼要決定、選擇的實際差別），再問**一件事，一次一題**。
- 技術縮寫與專案黑話首次出現附一句白話解釋。
- 選項寫「選了會發生什麼」的完整敘述；推薦項排第一並附理由；關鍵對比用 preview 文字圖。
- 至少涵蓋技術實作／UI-UX／edge cases／取捨；**不問顯而易見的問題，要挖 owner 沒想到的困難點**。
- 細節層級的分歧同樣可以做丟棄式原型實測拍板。

完成後完整規格**補進 SPEC.md（接在方向決議之後）**，每題留「決議＋理由」表列；涉 UI 必須有**可驗收的 UI/UX 條目**（畫面狀態、互動流程、無障礙要求）。

走完整路但訪談題很少時，可與 owner 商量把 SPEC＋PLAN 合寫；整包都簡單的應在開工分流時就走精簡路（`phases/lean.md`）。審查路數照規模分級，不因任何精簡再縮。

→ Checkpoint。
